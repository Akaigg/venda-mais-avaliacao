# ADR-003: Seleção de Biblioteca de Conexão com Banco de Dados SQL Server

**Status:** Aceito  |  **Data:** 09/06/2026  |  **Autores:** Matheus Karpinski, Vitor Machado Blume, Rhuan José Voltolini, Marcelo Momm

## Contexto
Para dar continuidade ao desenvolvimento da Plataforma de Inteligência Operacional VendaMais, os microsserviços de ingestão precisam extrair dados de tabelas do ERP. Era necessário avaliar qual biblioteca Python apresenta melhor performance de tempo de execução e carregamento de registros em memória RAM quando executada dentro do Azure Functions.

## Critérios de Avaliação
Uma Prova de Conceito foi executada efetuando buscas completas `SELECT *` na tabela `erp.titulo_receber`, contendo uma volume de 183 registros. O teste mediu o tempo total de conexão, execução da query e fetching integral dos dados para a memória compartilhada, calculando a média sobre 2 execuções consecutivas para cada biblioteca.

## Decisão
Adotar a biblioteca **`pyodbc`** como o driver padrão para as operações de leitura e ingestão direta no banco de dados SQL Server. 

Os testes empíricos apresentaram os seguintes resultados consolidados:
- **`pyodbc`**: Tempo médio de 0,2751 segundos por consulta completa.
- **`pymssql`**: Tempo médio variante entre 0,2942 e 0,3017 segundos por consulta completa.

## Consequências
- (+) **Performance e Eficiência:** O `pyodbc` provou ser aproximadamente 6.5% a 8.8% mais rápido no fetch de memória no ambiente serverless comparado ao `pymssql`.
- (+) **Estabilidade:** Utiliza o ODBC Driver 18 for SQL Server, recomendado oficialmente pela Microsoft para conexões em ecossistemas Azure.
- (-) **Dependência de Infraestrutura:** Exige que o driver ODBC correto esteja instalado no ambiente.

## Alternativas rejeitadas
- **pymssql:** Embora dispense drivers adicionais a nível de SO, apresentou maior latência média durante o processamento e alocação das linhas para a memória RAM.
