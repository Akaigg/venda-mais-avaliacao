# ADR-002: Estratégia de Armazenamento de Dados Processados

**Status:** Aceito  |  **Data:** 2026-04-07  |  **Autores:** Matheus Karpinski, Vitor Machado Blume, Rhuan José Voltolini, Marcelo Momm
## Contexto

Após a ingestão e transformação dos dados, é necessário armazenar as informações limpas, normalizadas e modeladas para consumo pelo Power BI. 
O diagrama C4 Nível 2 define dois containers de armazenamento: Data Lake (Azure Blob Storage) para dados brutos e Banco de Dados para os dados tratados, que deve atuar como fonte única.

## Decisão

- Adotar **Azure SQL Database (Serverless)** como container principal para o armazenamento dos dados processados e normalizados. 
- O Serviço de Transformação de Dados irá ler do Data Lake, aplicar as regras de negócio e gravar os dados no Azure SQL Database.

## Consequências

- (+) Excelente performance em joins e consultas analíticas
- (+) Suporte nativo a relacionamentos e integridade referencial
- (+) Conexão direta e otimizada com Power BI Service
- (+) Governança e manutenção mais simples para a equipe de TI
- (+) Forte rastreabilidade dos dados tratados

- (-) Custo mais elevado que armazenamento apenas em arquivos (mitigado pelo tier Serverless)
- (-) Menor flexibilidade para dados semi-estruturados
- (-) Vendor lock-in com motor SQL Server

## Alternativas rejeitadas

- Apenas Azure Blob Storage + Parquet; fraca performance em joins complexos e menor governança para relatórios
- Azure Cosmos DB; não ideal para modelo relacional e relatórios analíticos tradicionais
- Azure Synapse Dedicated SQL Pool; excessivamente caro e complexo para o volume atual da empresa
